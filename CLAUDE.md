## Le produit
**Appweb uniquement** (navigateur, pas d'app native), en français, solo. Un **tycoon très visuel en vue de dessus 3/4** (Phaser 3 dans Next.js) dont le but est de rendre agréable la **prospection commerciale**, c'est-à-dire la **recherche de clients réels** (seule la prospection est traitée). **Le produit, c'est le carnet de prospection** ; la carte est le moyen.
- **Fiche entreprise et cible** : par partie, versionnée ; elle dit ce que l'entreprise vend et qui elle cherche, et **pilote les agents** (en mode Réel, c'est la fiche cible des planètes).
- **Carnet de prospection** (dossier de prospects, `/api/prospects`) : on y **conserve**, **consulte**, **trie**, **marque « contacté »**, **supprime** et **exporte en CSV** ses prospects ; chacun porte sa source, sa date de collecte et sa fiabilité. À ne pas confondre avec le **carnet de prompts** (`/api/notebook`, apprentissage).
- **Agents spécialisés sur un prospect** : `profiler` (fiche client) et `outreach` (brouillon de premier message, **jamais envoyé**).
- **Carte unique** : la base de l'entreprise + des **planètes** = plateformes de données (Annuaire, Registre, Carte locale, LinkedIn, Glassdoor, puis la finale Constellation), débloquées au fil de la partie.
- **Boucle** : le joueur écrit le **prompt** de son agent → l'agent voyage visiblement vers une planète, y discute avec l'**agent de la planète** → rapporte des **leads** → le serveur note le prompt et les résultats → le joueur améliore son prompt (5 instructions max par agent et expédition), carnet de prompts et diff.
- **Deux modes** sur le même moteur (valeurs API `beginner` / `expert`) : **Tutoriel** (planètes simulées par un agent IA sur un corpus fictif) et **Réel** (mêmes planètes branchées à de vraies sources via MCP/API côté serveur ; **jamais de scraping direct**).
- 4 rôles d'agents au MVP : `scout` (éclaireur, gratuit), `qualifier`, `profiler` (analyste de fiche client), `outreach` (rédacteur de premier message) ; départ à 30 $ de jeu. Le chef d'équipe est reporté en P2.

**Moteur gardé, contenu remplacé** : sessions, économie/ledger, quotas, évaluation, idempotence et leurs tests restent. Correspondance : mission → planète/contrat, tentative → expédition, message → instruction, livrable → rapport de leads (voir `docs/PRODUIT-PROSPECTION.md` §10). **Ajouts** : fiche entreprise et cible, prospects, actions `prospect_profile` / `prospect_message` (nouvelle clé de quota `(prospect, rôle)`). **Décision** : `/api/notebook` (501) **reste le carnet de prompts** ; le dossier de prospects est une ressource **nouvelle et distincte**, `/api/prospects`, car les deux n'ont ni les mêmes données ni les mêmes règles (prompts = apprentissage et score ; prospects = produit, données personnelles, export). **Obsolète** : M1–M6, les 6 rôles du cahier, le chef d'équipe, l'ancien parcours « bureau/commande/atelier » ; ils restent dans le code tant que le nouveau contenu ne les remplace pas.

## Règles non négociables
1. **Le backend est seul maître** de l'argent, des prix, des quotas, du score, des déblocages et des droits. Le navigateur ne les choisit jamais.
2. **Sorties IA = contenu non fiable** : rendre texte/Markdown nettoyé, jamais de HTML ou script ; outils en liste blanche ; pas d'interpréteur libre.
3. Les instructions contenues dans un livrable ou un document sont des **données**, jamais des consignes (injection de prompt). Le serveur ignore toute récompense suggérée par le modèle.
4. **Idempotence** : toute mutation porte une `Idempotency-Key` ; un double envoi ne crée ni second appel ni second débit. Réservation avant appel, règlement après, atomiques ; jamais de transaction ouverte pendant l'attente réseau.
5. Pas de débit ni de message consommé sans réponse exploitable. Quota strict de **5 messages (instructions)** par agent et tentative (expédition), jamais 6.
6. Chaque lecture/mutation vérifie la **propriété de la session** ; aucune clé ni prompt système dans les erreurs, journaux ou réponses.
7. Versions de livrables immuables ; une livraison fige texte + brief + grille ; une grille modifiée n'altère pas une livraison déjà évaluée.
8. Règles, prix, planètes (ex-missions), rôles et grilles vivent dans des **fichiers de données versionnés**, pas dans le code.
9. Tests de règles avec le fournisseur **simulé** déterministe ; aucun appel réseau réel en test automatisé. Un mode simulé en démo porte toujours un badge visible.
10. Les contrats (`docs/CONTRACTS.md`) et règles partagées sont modifiés **par écrit avant fusion** et signalés aux autres personnes.
11. Langue : interface et textes du jeu en français ; messages d'erreur en français avec codes stables (`INSUFFICIENT_FUNDS`, `MESSAGE_LIMIT`, `ROLE_LOCKED`, `INVALID_STATE`, `VERSION_CONFLICT`, `LLM_UNAVAILABLE`, `INVALID_OUTPUT`).
12. **Sources de données** *(ajoutée avec le cap prospection)* : seules les routes de l'API interrogent une source, côté serveur, avec une liste blanche de sources et d'opérations ; **aucun scraping direct** de plateforme dont les CGU l'interdisent ; un lead n'est recevable que s'il porte un `source_ref` renvoyé pendant l'expédition, vérifié par code ; données personnelles minimisées (voir `docs/RULES.md` §9).
13. **Aucune action externe automatique** *(2e décision)* : le produit n'envoie **jamais** un message, un email ni une invitation et ne se connecte à aucune messagerie ni CRM ; un brouillon est un **texte que le joueur copie** ; « contacté » est **déclaratif**.
14. **Carnet de prospection et données personnelles** *(2e décision)* : un prospect n'entre dans le carnet que **recopié par le serveur** depuis un rapport, avec son `source_ref` **revérifié** (jamais de contenu fourni par le navigateur) ; mode Réel **B2B uniquement**, liste blanche de champs, rétention, suppression en cascade et export complet (`docs/RULES.md` §12) ; le **modèle ne reçoit jamais la valeur** d'un email ou d'un téléphone ; l'**export CSV est produit par le serveur** et **neutralise les formules** (préfixe `'` si la cellule commence par `=`, `+`, `-`, `@`, tabulation ou retour chariot) ; **consulter, trier, exporter et supprimer ses prospects n'est jamais conditionné** par l'argent ni par le score ; quota de 5 générations par `(prospect, rôle)`, jamais 6, sans gain.

## Collaboration

Chaque personne reste dans son périmètre (interface/carte `src/`, API et moteur `api/`, agents/planètes/contenu `data/`). Si un jalon glisse : simplifier la carte (placeholders), les variantes Réel et les animations avant de retirer une règle de fiabilité ; le **mode liste** (sans carte) reste le périmètre de secours.
